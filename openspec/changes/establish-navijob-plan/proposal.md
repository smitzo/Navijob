## Why

NaviJob needs one agreed feature scope, a serious visual design process and milestone tracking before product implementation. Existing research and demonstration screens do not establish a production recruitment workflow.

## What Changes

- Define the first release, deferred add-ons, candidate/recruiter/operator journeys and implementation dependencies in `PRODUCT_PLAN.md`.
- Establish three comparable visual concepts and a design brief; the user selects the direction.
- Add an OpenSpec delivery board with Backlog, Todo, In progress, Review, Done and Archived states.
- Create proposal, design, scenario specifications and task lists for each delivery milestone.
- Keep AI agents and external-site automation outside the first release.

Non-goals: implement application features, choose a visual direction, alter production data, install global Codex shortcuts, publish the site or claim completed hiring integrations.

Dependencies: existing repository and founder research; no product milestone must be implemented to complete this documentation milestone.

## Capabilities

### New Capabilities

- `delivery-planning`: Evidence-based milestone tracking, scope boundaries and visual selection workflow.

### Modified Capabilities

None. This change documents the delivery process and does not assert new application behavior.

## Impact

Adds project documentation, OpenSpec configuration, local workflow skills and image concept artifacts. No runtime application, database schema, billing or deployment changes.
